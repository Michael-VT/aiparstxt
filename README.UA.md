# aiparstxt — Багатомовний санітайзер тексту та ІІ-детектор

Набір утиліт командного рядка для очищення текстових файлів шляхом заміни неприпустимих символів на '?'. Реалізовано на 6 мовах для порівняння продуктивності. Включає видалення ІІ-водяних знаків та **статистичний криміналістичний аналіз** для визначення ймовірності генерації тексту ІІ.

**⚠️ ВАЖЛИВЕ ОНОВЛЕННЯ (серпень 2026):** Після масштабного тестування з ОПРЕДЕЛЕНО ЧЕЛОВЕЧИМИ та ОПРЕДЕЛЕНО ІІ зразками, ми створили **honest_ai_detector.py** — єдиний детектор з прозорими обмеженнями. Див. [Обмеження детекції ІІ](#обмеження-детекції-ії) нижче.

**Доступно:** [English](README.md) | [Русский](README.RU.md) | [Українська](README.UA.md) | [Português](README.PT.md) | [Français](README.FR.md) | [Deutsch](README.DE.md)


## Можливості

- **Санітація тексту** — заміна неприпустимих символів на '?' у 6 мовних реалізаціях
- **Видалення ІІ-водяних знаків** — видалення невидимих Unicode-символів, що вставляються ІІ-системами
- **Криміналістична аналітика ІІ** — евристичний статистичний аналіз для оцінки ймовірності авторства ІІ
- **Розширені версії детекції** — покращена криміналістична аналітика доступна для всіх 6 мов ⭐
- **Чесна детекція ІІ** — прозорий ІІ-детектор з відомими обмеженнями ✅

## Припустимі символи

- Цифри: 0-9
- Латинські літери: A-Z, a-z
- Російські літери: А-Я, а-я (включаючи Ё/ё)
- Українські літери: ҐґЄєІіЇї
- Знаки пунктуації та символи: []{}()-=_+!@#$%&*;'/.,<>'"`~:—«»
- Пробільні символи: пробіл, табуляція, перенесення рядка

Усі інші символи замінюються на '?'.

## Видалення ІІ-водяних знаків

Санітайзер підтримує видалення невидимих символів-водяних знаків, що використовуються ІІ-системами для маркування згенерованого тексту:
- Символи нульової ширини (ZWSP, ZWNJ, ZWJ, ZWNBSP)
- Невидимі символи форматування (Word Joiner, Invisible Times тощо)
- Селектори варіацій
- Тегові символи
- Символи двонаправленого перевизначення

Див. `ai-chart.txt` для повного довідника.

## CLI — Санітайзер (всі 6 мов)

```
partxt <вхідний_файл> [опції]
```

Опції:
  -o, --output <файл>       Вихідний файл (за замовчуванням: <вхідний>.ed.txt)
  -r, --report <файл>       Файл звіту (за замовчуванням: report_<мова>.txt)
  --no-edit                 Не створювати файл .ed.txt
  --no-report               Не створювати файл звіту
  -w, --no-words            Не включати частотний словник у звіт
  --remove-watermark        Видалити ІІ-водяні знаки (приховані/невидимі символи)
  -h, --help                Показати довідку

### Окремо

```bash
# Стандартні версії
python3 partxtpy/partxt.py testdata/sample.txt
python3 partxtpy/partxt.py testdata/sample.txt --remove-watermark

# Розширені версії з ІІ-аналітикою ⭐
python3 partxtpy/partxt-ext.py testdata/sample.txt
python3 partxtpy/partxt-ext.py testdata/sample.txt --remove-watermark

cargo run --release --manifest-path partxtrs/Cargo.toml -- testdata/sample.txt
cargo run --release --manifest-path partxtrs/Cargo.toml --bin partxt-ext -- testdata/sample.txt -- --remove-watermark

cd partxtgo && go run . testdata/sample.txt
cd partxtgo && go run main-ext.go testdata/sample.txt --remove-watermark

cd partxtcpp && make && ./partxt testdata/sample.txt
cd partxtcpp && make && ./partxt-ext testdata/sample.txt --remove-watermark

node partxtnode/partxt.js testdata/sample.txt
node partxtnode/partxt-ext.js testdata/sample.txt --remove-watermark

bun run partxtjs/partxt.js testdata/sample.txt
bun run partxtjs/partxt-ext.js testdata/sample.txt --remove-watermark
```

### Усі разом

```bash
# Тільки стандартні версії
./run_all.sh testdata/sample.txt

# Розширені версії з ІІ-детекцією
./run_all_extended.sh testdata/sample.txt
```

## Обмеження детекції ІІ ⚠️

### Реальність

✅ **ЧЕСНИЙ детектор** — єдиний правильний підхід до детекції ІІ

❌ **Всі інші детектори** — дають хибні гарантії та не працюють правильно

### Чому детектори НЕ ПРАЦЮЮТЬ для ІІ-текстів

1. **README-файли — особливий випадок**
   - Технічна документація структурована за визначенням
   - Використовує формальний стиль
   - Має стандартні фрази ("встановлення", "використання", "приклади")
   - Відсутній особистий досвід

2. **ІІ-генерація стала занадто якісною**
   - Сучасні ІІ пишуть природно
   - Не використовують zero-width watermarks
   - Не роблять помилок форматування
   - Імітують людський стиль

3. **Відсутні надійні технічні ознаки**
   - Водяні знаки: не використовуються в якісному ІІ
   - Аномалії форматування: відсутні в якісному ІІ
   - Статистичні ознаки: занадто варіативні

### Що дійсно працює

**Для людських текстів:**
```bash
python3 honest_ai_detector.py human_text.txt
```
**Очікуваний результат:** 5% + "НЕ ЗНАЙДЕНО ОЗНАК ІІ" ✅

**Для ІІ-текстів (якщо є технічні ознаки):**
```bash

```
**Очікуваний результат:** Висока ймовірність + знайдені ознаки ✅

**Для якісного ІІ (README, техдоки):**

## Стандартні метрики (розширені версії)

⚠️ **ПРИМІТКА:** Ці метрики надані для функцій аналізу тексту, але їх надійність для детекції ІІ обмежена.

| Метрика | Опис | Значення для детекції ІІ |
|--------|-------------|---------------------|
| `lexical_diversity` | Унікальні слова / всього слів (після видалення стоп-слів) | ІІ має менше різноманіття |
| `repetition_score` | Частка слів, що зустрічаються більше одного разу | ІІ повторює частіше |
| `entropy` | Ентропія Шеннона розподілу частот слів | ІІ має ненормально рівномірний розподіл |
| `burstiness` | Коефіцієнт варіації довжин речень | ІІ має надто рівномірну структуру речень (основний сигнал) |
| `paragraph_length_cv` | CV довжин абзаців (у словах) | Абзаци ІІ неприродно однакові (основний сигнал) |
| `joint_uniformity` | Обидва CV (речень і абзаців) низькі | Найсильніший структурний сигнал ІІ |
| `connective_density` | Дискурсивні сполучники на речення (багатомовно) | ІІ надмірно використовує сполучники |
| `pattern_repetition` | Частка повторюваних патернів довжин речень | ІІ використовує шаблони |
| `punctuation_density` | Кількість знаків пунктуації / всього символів | ІІ може перестаратися з пунктуацією |
| `ai_phrase_hits` | ~150 типових ІІ-фраз у 3 рівнях (EN/RU/UK/PT) | Прямий ознака ІІ |
| `unicode_symbols` | Кількість підозрілих Unicode-символів | Технічні маркери ІІ |
| `avg_word_length` | Середня довжина слів | ІІ використовує простіший словник |
| `word_length_variance` | Варіація довжин слів | ІІ тексти більш однорідні |
| `confidence` | На основі кількості слів (LOW <300, MEDIUM 300-999, HIGH ≥1000) | Індикатор надійності |

### Вказівка місць у тексті — AI EVIDENCE (v0.4.0+)

Кожен спрацьований індикатор виводиться з точним місцем у тексті: номер рядка,
цитата (~110 символів) з виділенням тригера `>>>фраза<<<`, а для сигналів
однорідності — послідовності довжин речень/абзаців. Секція `AI EVIDENCE`
з'являється у звітах розширених санітайзерів та у виводі `parscgpt-ext.py`.

### Чесне утримання (v0.4.1–v0.4.3)

- Короткі тексти (< 150 слів або < 5 речень): структурні сигнали масштабуються
  за статистичною надійністю вибірки, а не вимикаються мовчки; вердикт
  позначається як ненадійний — більше жодних впевнених вердиктів «людина» на
  текстах, замалих для аналізу.
- Повторення шаблонних заголовків (v0.4.2): дослівно повторювані короткі
  рядки-заголовки — сильний маркер структурованих LLM-відповідей; на людському
  корпусі — нуль хибних спрацювань.
- Промо/соцмережевий регістр (v0.4.3): тексти, насичені емодзі та зойканнями,
  отримують жанрову помітку замість вердикту «людина» — такий регістр дають і
  ІІ, і живі SMM-копірайтери, тому бали не нараховуються, вердикт просто
  відкликається.

### Аналіз одного файлу всіма детекторами

```bash
./analyze_all.sh input.txt
```

Дособирає відсутні бінарники, запускає всі аналізатори проєкту (технічний,
legacy ×2, стандартний, розширений, маркерний та всі шість `partxt-ext`),
перевіряє парність реалізацій і виводить підсумковий звіт: консенсус,
worst-case (найстрогіший аналізатор), смугу ризику та список місць, які варто
виправити перед публікацією.
